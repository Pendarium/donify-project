# 1. Brainstorming and MVP

## Project Overview

Donnify is a gamified platform designed to improve the visibility of charitable associations and encourage community engagement through donations and volunteer participation.

The platform allows users to easily discover nearby associations, understand their needs, and contribute through material donations or volunteer activities.

The MVP focuses on accessibility, association visibility, and volunteer management.

---

## Evaluation Criteria

| Criterion | Analysis | Conclusion |
|---|---|---|
| Impact | Responds to a real social need by improving association visibility and encouraging participation. | High Social Value |
| Feasibility | Achievable with current technical skills and realistic MVP limitations. | Feasible MVP |
| Technical Alignment | Most technologies are already mastered, while some require additional learning. | Requires Adaptation |
| Scalability | Strong potential for future feature expansion and mobile deployment. | Very Promising |
| Risk | Time constraints and technical complexity may impact development speed. | Requires Scope Control |

---

## Overall Conclusion

The project is achievable within the defined timeframe if the MVP remains focused on core functionalities and scope limitations are respected.

---

## Reflection and Ideation Process

The project idea was validated through research and analysis of:

- Real-world problems
- Existing solutions
- Current technology trends
- User engagement strategies

The “How Might We” method was used to reformulate the initial problem into actionable opportunities:

- How might we improve association visibility?
- How might we simplify volunteer participation?
- How might we encourage donations through modern digital tools?

This process confirmed the relevance and feasibility of the project.

---

## Final Idea

Donnify is a platform that centralizes charitable associations and simplifies volunteer engagement through a modern and accessible interface.

---

### Solution

A web and mobile platform that centralizes associations, volunteer offers, and donation information.

### Target Users

- Volunteers
- Local associations

### Platform

- Web Application
- Mobile Application

### Reason for Choosing This Idea

- Strong social impact
- Personal motivation

- Expandable future potential

# External and Internal APIs Documentation

## Overview

Donnify uses both external APIs and internal REST API endpoints to manage authentication, association data, volunteer offers, and platform interactions.

The backend follows a REST architecture using NestJS and exchanges data in JSON format.

---

## External APIs

## RNA API

### Purpose

The RNA API is used to verify the legitimacy of charitable associations registered in France.

### Why It Was Chosen

- Official government data source
- Reliable association verification
- Simplifies the certification process
- Improves platform trust and security

### Main Usage

- Validate RNA numbers
- Automatically certify eligible associations
- Retrieve official association information

### Example Usage

```http
GET /api/rna/{rna_number}
```

# Plan SCM and QA Strategies

## Software Configuration Management (SCM)

### Overview

As the project is currently in the design phase, the SCM strategy defines how the codebase will be managed once development starts.

The project will use Git and GitHub for version control.

---

## Branching Strategy

A simple branching model will be used:

| Branch | Purpose |
|---|---|
| `main` | Stable version of the project |
| `develop` | Main development branch |

---

## Planned Workflow

Once development begins, the workflow will follow these steps:

1. All development will be done on the `develop` branch
2. Features will be developed incrementally
3. Regular commits will be used to track progress
4. Once stable, `develop` will be merged into `main`
5. The `main` branch will always represent the production-ready version

---

## Commit Strategy

Commits will follow a structured naming convention:

```bash
feat: add authentication system
feat: implement volunteer offers module
fix: resolve navigation issue
docs: update project documentation
refactor: improve architecture structure
```

---

## Code Management Principles

- No direct commits on `main`
- Feature-based development workflow
- Clear and atomic commits
- Regular synchronization between branches

---
